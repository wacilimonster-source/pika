Pika（哔咔）源列表页展示作品更新时间 · 可行性研究

项目：G:\game\nw\pka\pika · 研究日期：2026-09-02 · 状态：仅调研，未改动任何业务代码
结论先行：这不是一个"要不要加 UI"的问题，而是一个"数据到底有没有"的问题。
  • UI 层已经做了 —— 网格卡片 ComicGridView 早已在封面下方渲染 comic.updatedAt.take(10)，字段为空才不显示。
  • 大部分列表的数据链路也已接通 —— 搜索 / 收藏 / 排行榜 / 随机 / 关注流 都走 Doc.toSummary()，已把 updated_at 传下去。
  • 剩下两个真问题：① 分类浏览接口究竟返不返回 updated_at（项目注释与模型声明互相矛盾）；② 详情页「猜你喜欢」既缺数据、卡片本身也没有时间行。

网格卡片底部已经有一行"更新时间"，只是有数据时才显示，所以看起来像"没做"。

关于"浏览接口不带时间字段"这条注释

它来自 v1.5.7 提交（366ef77），原文：

// 作者作品用全文搜索（关键字=作者名）拉取：浏览接口不带时间字段，
// 搜索接口按更新时间返回（实测作者名可完全匹配该作者全部作品）。

这句话当时的语境是"为了让关注流能按更新时间排序，作者作品改走搜索而不是浏览"，暗示浏览接口的条目拿不到时间。 但代码里 Doc 又明确声明了 @SerialName("updated_at")，而 Doc 恰恰就是浏览接口的解析模型—— 两者不可能同时成立。这是本次研究最需要实测澄清的一点，因为分类浏览是主列表页。

交叉验证时还发现：两个 Go 库（gopica / pica-go）的列表结构体确实都没有 updated_at， 但它们同时也缺 totalViews、totalLikes、tags——而这些字段本项目确定在用且能显示。 说明这些库只是作者懒得声明，并不能证明服务端不返回。

四、顺带发现的排序隐患

BrowseViewModel 与 AuthorViewModel 对哔咔源会在客户端按 updatedAt 字符串重排，以支持"新到旧 / 旧到新"切换： 
ComicSort.DD -> filtered.sortedByDescending { it.updatedAt }
ComicSort.DA -> filtered.sortedBy { it.updatedAt }
  • 若分类浏览的 updatedAt 全为空：sortedBy 是稳定排序，会原样保留服务端顺序 → 目前不出错，但本地重排实际是空转。
  • 若部分有部分无：有时间的会整体挤到一端，顺序错乱 → 会出 bug。

所以澄清"浏览接口到底有没有时间"不只是显示问题，也关系到分类页排序的正确性。

五、三种处置方案与代价

方案做法代价 / 评价
A. 零改动 先实测确认各接口字段情况；若搜索/收藏/排行榜已有时间，则这些页面本来就显示了，只是你没注意 0 成本。前提是实测证明数据确实到位
B. 补齐推荐页 给 RecommendComic 加 @SerialName("updated_at") 字段 + toSummary() 传入；如服务端不返回则保持留空 1～2 行代码。显示效果取决于服务端，属"有则更好"
C. 强攻分类浏览 若实测确认浏览接口无时间：改为对列表逐个调 comics/{id} 详情接口补时间 不推荐。每页 40 条 = 40 次额外请求，哔咔限速约 2 次/秒，会直接触发 429/1023，且拖慢首屏
推荐路径：先跑一次探测脚本 → 拿到真实字段 → 再决定 A / B。C 方案基本可以排除。

六、已备好一次性探测脚本

已新增 tools/pica-api-check.mjs（只读：1 次登录 + 若干列表 GET）。请求头与签名与 App 完全一致，会遍历 7 个列表接口， 打印每个接口的首条目完整字段名，并明确标记 updated_at / created_at 是否存在及示例值。约 30 秒出结果。

# 或复用已有 token（跳过登录）
PICA_TOKEN=xxx node tools/pica-api-check.mjs

已实测确认的两件事（2026-09-04）

① Node 的 fetch 不会被 Cloudflare 拦。挂代理后 6 个接口全部返回标准 HTTP 401 / code=401 unauthorized， 说明签名、请求头、域名轮换都正确，服务端正常响应——不是被 Bot Management 拦截（被拦会表现为 403 或 code=1023）。 所以脚本本身可用，随时能跑。
② 哔咔所有列表接口都必须鉴权，免登录一律 401，没有可以绕开的公开列表接口： 
categories            401 unauthorized
comics?c=             401 unauthorized      ← 分类浏览
comics/leaderboard    401 unauthorized
comics/random         401 unauthorized
comics/advanced-search 401 unauthorized     ← 搜索
users/favourite       401 unauthorized
因此想跑探测，必须提供一个能登录的哔咔账号（邮箱+密码 或 token）。用户本次选择暂不测。

替代方案（无需凭据）：在真机上打开 搜索页 / 收藏页 / 排行榜，看卡片封面下方有没有一行灰色小字日期（如 2026-05-06）。 有 → 说明该接口确实返回了 updated_at，这些页面本来就显示了；没有 → 说明数据为空。

七、下一步建议

  1. 最快路径：真机目视确认（零成本、无需凭据）。打开搜索页 / 收藏页 / 排行榜，看卡片封面下方有没有灰色小字日期。 有 → 这些接口确实返回 updated_at，页面本来就显示了；没有 → 数据为空。
  2. 想一次性拿到全部 7 个接口的确定结论：给我哔咔账号跑一次 tools/pica-api-check.mjs（脚本已验证可用，只差凭据）。
  3. 若确认分类浏览没有时间：建议接受留空，同时移除客户端按 updatedAt 的重排，改回信任服务端 s=dd/da 排序，消除隐患。
  4. 若分类浏览有时间却没显示：则是解析/缓存问题，需要单独排查。
  5. 「猜你喜欢」按方案 B 处理：补字段，有就显示，没有也不影响。
