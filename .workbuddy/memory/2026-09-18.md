# 2026-09-18

## 修复「作品收藏无效」+ 发版 v1.5.50 (build 76)

### 根因（真机 + 真实接口双向实证，不是推测）
哔咔收藏端点的响应是 `{"action":"favourite"}` / `{"action":"un_favourite"}` —— **英文机器码**。
而 `PicacgSource.favourite` 从 v1.5.44（`7dc5137`）起按中文文案判断：

```kotlin
return resp.action.contains("收藏") && !resp.action.contains("取消")   // 对 "favourite" 恒为 false
```

`"favourite".contains("收藏") == false` → 方法**永远返回 false**。后果：
服务端其实收藏成功了，但 `_favourited` 被回写成 false，心形不点亮 → 用户以为没收藏 → 再点一次（第二次切换**真的取消掉**）→ 最终「收藏无效」。

- 更早的历史：`1321ff0`(v1.5.31) 之前是 `contains("藏")`（同样恒假）；v1.5.31 改成「含藏→true，非空→true」，即恒真（能点亮但取消后不熄灭）。**这个判定被反复改错三次**，每次都只改了判断字面量、没去验证服务端到底返回什么。
- v1.5.48 引入的 `_favourited.value = detail.isFavourite` 是对的，但它只能修「进入详情页显示错」，修不了点击那一刻的判定。

### 实测证据（用 App 完全一致的签名/头打真实接口，token 从设备 DataStore 取）
```
POST /comics/{id}/favourite  → {"action":"favourite"}     （详情回读 isFavourite=true，收藏列表 29→30）
POST /comics/{id}/favourite  → {"action":"un_favourite"}  （详情回读 isFavourite=false，收藏列表 30→29）
```

### 修法（`core/source/PicacgSource.kt`）
1. `parseFavouriteAction(action)`：兼容机器码与中文文案。**必须先判否定**（`un_`/`un-`/`取消`），否则 `un_favourite` 会因含 `favourite` 被判成已收藏。
2. 无法识别的文案返回 null → 抛 `PicaException`（以前静默返回 false，等于对用户说谎）。
3. 尊重 `add` 参数：端点是切换型，返回状态 ≠ 期望状态时（本地与他端失步）**再切一次纠正**，保证返回值恒等于调用方请求的 `add`。

### 真机验证（MuMu，`adb -s 127.0.0.1:16384`，release 包覆盖安装保留登录态）
| 场景 | 结果 |
|---|---|
| 点收藏 | 心形点亮；详情 `isFavourite=true`；收藏列表 29→30 且能看到该作品 |
| 退出详情再进 | 心形仍为实心（持久化 + `detail.isFavourite` 初始化都对） |
| 再点一次取消 | 心形熄灭；`isFavourite=false`；列表 30→29 |
| **失步纠正**（带外 API 先收藏，App 界面仍是空心） | 点一次后心形点亮、服务端 `=true` —— 纠正分支按预期触发 |
| 账号状态 | 测试后完全还原（29 项收藏、该作品未收藏） |

### 仍存疑（未改，留待有 JM 账号时验证）
`JmcomicSource.favourite` 返回的是「请求是否成功」（`runCatching{ favoriteToggle }`），**取消收藏时也返回 true** → JM 心形会停在已收藏。修法应是成功即返回 `add`（JM 端点用 `type=1|0` 显式指定目标态，不是切换），但 `type=0`（取消）字段本身标注为「待真实账号验证」，本机无 JM 账号，**不敢盲改**。

### 复用要点
- 设备 DataStore 里的 pica token 可直接取出来打真实接口：`adb root` 后 `cat /data/data/com.pika/files/datastore/pika_prefs.preferences_pb`，再 `grep -ao 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9[A-Za-z0-9._-]*'` 提出 JWT。**这是排查源侧 bug 最快的手段**，比反复点 UI 猜快得多（App 的 LogStore 只在内存、重启即失，logcat 也没有收藏日志）。
- 想验证「本地失步」这类分支，就用带外 API 改服务端状态，App 界面会自然处于过期态 —— 不用改代码造场景。
- `adb root` 会重启 adbd，紧接着的命令容易 offline，读文件要单独成批。
