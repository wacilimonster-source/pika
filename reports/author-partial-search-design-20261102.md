## 0. 一句话结论

点击作者时，**不再把整串署名原样当作作者身份**，而是先做一次本地「署名解析」，把
`张三 / 李四（翻译：王五）` 拆成多个**署名片段**：单一署名行为不变（一次点击直达）；
联合署名或带翻译的署名弹出一层轻量选择，用户点哪一段就按哪一段搜「署名包含它」的作品。
作者页顶部保留片段切换条，选错可原地换人；收藏/关注也以片段为身份。

## 1. 现状与问题（代码级核实）

### 1.1 当前链路

| 环节 | 现状 | 依据 |
|---|---|---|
| 详情页作者 | 整行可点击，把 `comic.author` 原样传出 | `ui/detail/ComicDetailScreen.kt:745-760` |
| 路由 | `author/{author}`，参数即整串署名 | `ui/MainScreen.kt:362-363, 376-387` |
| 作者页查询 | `browse(author = 整串)` → GET `/comics?a=整串` | `ui/author/AuthorViewModel.kt:56-85`；`network/PicaApi.kt:77-90` |
| 作者页标题/收藏 | 标题与收藏键都是整串署名 | `ui/author/AuthorScreen.kt:98-116` |
| 关注流里的作者 | 用**关键词搜索** `search(keyword = 整串)` 拉作品 | `ui/home/HomeViewModel.kt:473-483` |
| 本地作者收藏 | 以整串署名为唯一键持久化 | `data/AuthorFavourites.kt:27-70` |

### 1.2 问题拆解

1. **联合署名被当成一个人**
   署名 `张三 / 李四` 点击后查询的是完整字符串。若服务端 `a` 参数为精确匹配，
   只能找到署名恰好为 `张三 / 李四` 的作品；仅署名 `张三` 或仅 `李四` 的作品全部漏掉。

2. **翻译/角色信息污染作者身份**
   `张三（翻译：王五）` 里真正的作者是张三，王五是翻译。整串查询既找不到张三的独立作品，
   标题和收藏列表也会显示一整串噪声，收藏后关注流同样按整串搜索。

3. **两套查询语义不一致**
   作者页用 `browse(a=整串)`，关注流用 `search(keyword=整串)`。同一作者在两处结果可能不同；
   且关注流的搜索没有做「作者字段包含」校验，标题/标签命中的非该作者作品会混入
   （`HomeViewModel.kt:473-483` 只有关键词，没有作者过滤）。

4. **没有纠错出口**
   即使把整串查询改对，用户也无法在作者页里从 `张三 / 李四` 切到只含 `张三` 的结果，
   只能返回详情重新进。

### 1.3 已有可复用证据

关注流实现处有一条实测注释：**以作者名为关键词走 `comics/advanced-search`，能完全匹配该作者的全部作品**
（`HomeViewModel.kt:475-477`）。这说明关键词搜索覆盖作者字段，是本次「片段搜索」最可靠的服务端能力基础；
相比之下 `a` 参数是否支持子串尚未验证（详见 §6）。

## 2. 设计目标与非目标

### 目标

- **G1** 从任意复合署名中选出任意一段，搜索「署名包含该段」的全部作品。
- **G2** 单一作者零学习成本：仍然一次点击直达，不新增弹层。
- **G3** 作者页内可随时切换片段，不用返回详情重进。
- **G4** 收藏作者、关注更新以「片段」为身份，语义与作者页一致。
- **G5** 结果必须只包含署名命中的作品，不被标题/标签里的同名文字污染。
- **G6** 解析器可单测、可回退；解析不确定时永远保留「完整署名」与「手动编辑」出口。

### 非目标（本期不做）

- 不做跨源作者合并、作者别名库、拼音/模糊/近似匹配。
- 不改变搜索页的全文搜索语义（用户手动输入作者名仍走关键词搜索）。
- 不做「把收藏的复合署名批量拆成多个作者」的整理工具（可作后续）。
- 不引入服务端作者实体或新接口契约。

## 3. 核心概念

| 概念 | 定义 | 示例 |
|---|---|---|
| **原始署名** `origin` | 服务端 `author` 字段原值，展示与回退用 | `张三 / 李四（翻译：王五）` |
| **署名片段** `segment` | 解析后的一段可搜索文本 | `张三`、`李四`、`王五` |
| **角色** `role` | 片段在该署名中的身份，用于打标签 | 作者 / 原作 / 作画 / 脚本 / 翻译 / 汉化 / 其他 |
| **查询词** `query` | 实际用于检索的字符串，等于被选中的片段或完整署名 | `张三` |

一个关键约束：**只有 `segment`/`query` 会进入网络查询、收藏键和关注目标；`origin` 只用于展示与回退。**

## 4. 交互设计

### 4.1 详情页入口：先判断，再决定要不要弹层

```
解析 author
├─ 只有 1 个有效片段（或解析结果 == 原串）
│    → 点击整行，直接进入作者页（与今天完全一致，零新增步骤）
└─ ≥2 个有效片段
     → 点击整行，弹出「选择作者」底部弹层
```

- 详情页作者行视觉保持现状（主色文字 + 「查看作品 >」），不把多个片段塞进一行做小点击区，
  避免误触，也避免长署名在横向空间里挤压。
- 单作者场景不弹层，是为了不让 90% 的普通用户为少数复合署名买单。

### 4.2 「选择作者」底部弹层

```
┌─────────────────────────────────────────┐
│  选择要浏览的作者                        │
│  该署名包含多位作者或署名说明，选择其中  │
│  一部分即可搜索署名中包含它的作品。      │
│                                         │
│  原署名：张三 / 李四（翻译：王五）        │
│                                         │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ │
│  │ 张三     │ │ 李四     │ │ 王五 翻译│ │
│  └──────────┘ └──────────┘ └──────────┘ │
│                                         │
│  ┌─────────────────────────────────────┐│
│  │ 按完整署名查看「张三 / 李四（翻译…）」││
│  └─────────────────────────────────────┘│
│                                         │
│              手动编辑署名…               │
└─────────────────────────────────────────┘
```

- 片段以 Chip 呈现，点击即关闭弹层并进入作者页；不需要「确定」按钮。
- 非默认角色显示小号标签（`翻译`、`原作`、`作画`、`脚本`、`汉化`），默认作者不标。
- 「按完整署名查看」始终保留，作为解析错误时的兜底。
- 「手动编辑署名…」打开一个预填原串的单行输入框，用户自行删改后搜索（见 §4.6）。

### 4.3 作者页：片段切换条

进入作者页后，顶部在排序/状态筛选之上增加一行可横向滚动的片段 Chip：

```
← 张三                                  ♥
原署名：张三 / 李四（翻译：王五）

[张三✓] [李四] [王五·翻译] [完整署名]

新到旧  旧到新  最多喜欢
全部  连载中  已完结
────────────────────────────────
（作品网格）
```

- 标题显示当前片段（`张三`），副标题显示完整原署名，让用户知道自己在哪个上下文里。
- 点击其他片段**原地切换**：重置到第 1 页、回到顶部、重新加载，不新增返回栈。
- 当前片段与完整原串不同时，列表顶部或空态显示一句轻提示：
  「正在浏览署名中包含「张三」的作品」。
- 收藏按钮收藏**当前片段**；标题栏心形状态随切换片段刷新。
- 排序、连载状态、页码分页、分页回顶等现有行为保持不变。

### 4.4 收藏作者与关注流

- 收藏条目从「原串」改为「当前片段」，收藏列表显示干净的名字（`张三`），而不是整串。
- 关注流的 AUTHOR 目标同样使用片段搜索，并补上**署名包含校验**（见 §6.4），
  避免标题/标签命中混入。
- 旧收藏不做破坏性迁移：历史条目仍按原串工作；点进去后作者页的片段条可以继续拆分。

### 4.5 空态与纠错闭环

作者页无结果时按情况给出出口：

| 情况 | 文案与操作 |
|---|---|
| 当前是片段，且与原串不同 | 「没有找到署名包含「张三」的作品」＋「查看完整署名」＋「用关键词搜索」 |
| 当前是完整原串，且可拆分 | 「没有找到该署名的作品」＋「拆分署名重试」（重新弹选择层） |
| 当前是片段，且原串就是它 | 「该作者暂无作品」＋「用关键词搜索」 |

「用关键词搜索」跳到搜索页并带上 `keyword=当前片段`，复用现有 `search?keyword=` 路由。

### 4.6 手动编辑署名（兜底）

当解析器无法正确切分（例如 `/` 本身就是笔名的一部分、署名里混入社团名/邮箱/URL）时：

- 弹层底部「手动编辑署名…」打开输入框，预填原始署名，光标置于末尾。
- 用户删改后提交，按输入内容作为 `query` 搜索，`origin` 仍保留原串用于回退。
- 不采用「长按文字拖选一部分」方案：Compose 文本选择手势会和整行点击、横向滚动冲突，
  且小字号选择精度差、无法给角色打标签。手动编辑在同样成本下更可控。

## 5. 署名解析规则（纯函数，可单测）

解析器输出 `List<AuthorSegment>`，`AuthorSegment(text, role, index)`；解析只做「候选拆分」，
不追求 100% 正确——UI 永远提供完整署名与手动编辑兜底。

### 5.1 归一化

1. 全角转半角标点：`，→,`、`／→/`、`＆→&`、`：→:`、`（）→()`、`【】→[]`、`　→ `。
2. 去首尾空白，折叠连续空白。
3. 整体去前缀角色标签：`作者:`、`著:`、`Author:` 等。

> 不做的归一化：不改写日文假名/繁简、不做拼音化、不删除中间的点 `·`（`·` 常见于西文姓名，
> 如 `J·K·罗琳`，不能当分隔符）。

### 5.2 提取与拆分顺序

1. **括号组优先**：提取 `(...)`、`[...]`、`【...】` 中的内容。
   - 组内形如 `翻译: 王五` / `王五 翻译` / `原作` → 生成带角色的片段；
   - 组内只有角色词（`翻译`、`汉化`、`著`）→ 把该角色附着到**前一个姓名片段**上；
   - 组内是纯名字 → 生成角色为「其他」的片段；
   - 组内容若含多个分隔符，回到第 3 步继续拆。
2. **括号位置替换为分隔符**，避免 `张三(翻译:王五)/李四` 粘连。
3. **按分隔符切分**：`,` `/` `&` `;` `|` `+` `、` `\`、换行、以及两侧带空格的 ` x ` / ` × `。
   - **不切**：单个空格、`-`、`.`、`·`（保护 `Mary Jane`、`K/DA` 之外的西文姓名与复姓）。
4. **逐段清洗**：
   - 去前缀角色词：`作者|原作|作画|编剧|脚本|构成|监修|翻译|译者|汉化|著|绘|画|写真|出品|制作`
     及英文 `author|artist|writer|story|art|translator|translation|letterer|editor|illustrator|original|script`，
     允许后跟 `:`/空格；
   - 去尾部纯角色词（仅当与名字之间有空格或括号分隔）；
   - 去空段、纯角色词段。
5. **去重**：按 `trim + lowercase` 去重，保留首次出现的位置。
6. **数量守卫**：有效片段 > 6 时，保留前 6 个 + 完整署名兜底（避免弹层爆炸）。

> 最终至少返回 1 个片段；解析失败就返回 `[原始署名]`，此时详情页走「单作者直达」，
> 行为与今天一致。

### 5.3 角色识别

| 关键词 | 角色标签 | 是否默认显示标签 |
|---|---|---|
| （无） | 作者 | 否 |
| 原作、原著、original、story | 原作 | 是 |
| 作画、绘、画、art、artist、illustrator | 作画 | 是 |
| 编剧、脚本、script、writer | 脚本 | 是 |
| 翻译、译者、translation、translator | 翻译 | 是 |
| 汉化、汉化组 | 汉化 | 是 |
| 监修、构成、制作、出品、editor、letterer | 其他 | 是 |

角色只影响展示标签与排序提示，不影响能否被选中搜索。**翻译/汉化组同样可被搜索**，
因为用户可能正是在找某位译者的作品。

### 5.4 解析示例（将作为单测用例）

| 原始署名 | 片段（角色） |
|---|---|
| `张三` | 张三（作者） |
| `张三 / 李四` | 张三（作者）、李四（作者） |
| `张三，李四` | 张三、李四 |
| `张三 & 李四` | 张三、李四 |
| `张三 x 李四` | 张三、李四 |
| `张三（翻译：王五）` | 张三（作者）、王五（翻译） |
| `张三 (著) / 王五 (绘)` | 张三（作者）、王五（作画） |
| `原作：张三 / 作画：李四` | 张三（原作）、李四（作画） |
| `张三 原作、李四 作画` | 张三（原作）、李四（作画） |
| `张三 / 汉化：某某汉化组` | 张三（作者）、某某汉化组（汉化） |
| `作者：张三` | 张三（作者） |
| `J·K·罗琳` | 单个片段（不按 `·` 切） |
| `K/DA` | 单个片段（`/` 两侧无空格且整体很短 → 保留整串；同时提供完整署名兜底） |
| `Mary Jane` | 单个片段（不按空格切） |
| `张三 / 李四 / 王五 / 赵六 / 钱七 / 孙八 / 周九` | 前 6 个 + 完整署名 |

## 6. 查询策略（决定成败的部分）

### 6.1 先验证，再定实现

服务端行为必须在实现前用真实接口确认（本次设计阶段无可用登录态，只确认了未登录会 401）：

| 探针 | 目的 |
|---|---|
| `GET /comics?page=1&a=张三` 对比 `a=张三 / 李四` | `a` 是精确匹配还是子串/分词匹配 |
| `POST /comics/advanced-search` `keyword=张三`、`keyword=李四` | 关键词是否覆盖作者字段；部分姓名能否命中 |
| 对比两次结果的 `_id` 集合与 `author` 字段 | 判断召回范围、是否被标题/标签污染 |

已有证据：`HomeViewModel.kt:475-477` 的注释明确记录「作者名走关键词搜索可完全匹配该作者全部作品」，
因此关键词路径可用；`a` 参数作为更优路径待验证。

### 6.2 推荐实现：源内统一 `authorWorks` 方法

UI 不关心底层用哪个接口。在 `Source` 增加（或由 `PicacgSource` 单独实现）：

```kotlin
suspend fun authorWorks(
    query: String,          // 选中的署名片段
    page: Int,
    sort: ComicSort,
): PageResult<ComicSummary>
```

`PicacgSource` 内部按以下优先级选策略，并在会话内缓存「当前源可用策略」：

- **策略 A（首选，服务端支持子串时）：** `browse(author = query)`，服务端分页完整，客户端零过滤。
- **策略 B（已验证可行，兜底）：** `search(keyword = query, page, sort)` →
  **客户端只保留 `author` 命中该片段的条目**。
- 若 A 返回空但 B 有结果、或 A 的结果明显是精确匹配（返回条目的 author 均不等于 query 且不含 query），
  自动降级到 B；策略结果按源缓存，避免每页反复试探。

> 为什么 B 必须做客户端过滤：关键词搜索会命中标题/标签。作者页展示的是「该作者的作品」，
> 标题里恰好含「张三」的别人的作品不能混进来。

### 6.3 匹配规则

对 `author` 字段做归一化后匹配：

- **CJK 片段**：`author.contains(segment)`，大小写/全半角归一化后比较。
- **拉丁片段**：按词边界匹配，避免 `art` 命中 `Bart`：
  正则 `(?<![A-Za-z])segment(?![A-Za-z])`（忽略大小写）。
- 片段长度 < 2 的拉丁串（如 `X`）仅在词边界完全相等时算命中。

### 6.4 分页、去重与密度

策略 B 下每页可能被过滤掉一部分，设计如下：

- 每页仍按服务端页码请求；过滤后为空且不是末页时，**自动顺延下一页**，最多连续顺延 3 页，
  避免用户看到整页空白。
- 非空页按原样展示（不强行凑满 20 条）；页码条仍显示服务端页数。
- 拼接/顺延产生的结果按 `id` 去重。
- 客户端连载状态筛选沿用 `AuthorViewModel.applyFilterAndSort()`，不改变现有行为。

策略 A 下完全保持服务端分页，无上述处理。

### 6.5 排序

`search` 返回的 `Doc` 带 `updated_at`（`PicacgSource.kt:488-497`），作者页的「新到旧/旧到新」
会真正生效；顺带修复当前 `browse` 接口不返回时间字段时排序形同虚设的问题。

### 6.6 关注流对齐

`HomeViewModel` 的 AUTHOR 目标在 `search(keyword = name)` 之后补一层
`author` 包含校验（复用 §6.3 的匹配器），与作者页同一套语义；同时按 `id` 去重已有逻辑不变。
这样收藏「张三」后，关注流不会混入标题含「张三」的无关作品。

## 7. 数据与路由改动

### 7.1 路由

保留旧路由兼容，并增加可选参数：

```
author/{query}?origin={原始署名}&role={角色}
```

- `query`：实际搜索的片段；
- `origin`：原始署名，用于副标题与「完整署名」入口；缺省等于 `query`；
- `role`：可选，仅用于标题标签展示。

旧的 `author/{author}` 仍然可用（等价于 `query=origin=author`）。

### 7.2 收藏

`AuthorEntry` 语义调整：

- `author` 字段继续作为唯一键，但新写入时存**片段**；
- 可选新增 `origin: String? = null` 记录原始署名，用于收藏列表的次要说明（可不做）；
- 旧数据无需迁移：读取逻辑不变，旧条目继续按原串搜索与展示。

### 7.3 关注目标

`FollowTarget(name = 片段)`；`FollowSettings`/`FollowFeedCache` 结构不变。
若担心旧缓存里存的是复合原串，继续按原串搜索 + 包含校验即可，不会崩。

## 8. 边界与文案

| 场景 | 处理 |
|---|---|
| 署名就是单个作者 | 不弹层，直达作者页；收藏/关注存该名字 |
| 署名含 `/` 但是笔名（`K/DA`） | 解析器仍可能拆；弹层永远有「完整署名」兜底 |
| 署名含翻译但用户想找译者 | 译者作为片段可选，标「翻译」 |
| 署名含汉化组 | 作为「汉化」片段可选；不默认排在作者前面 |
| 署名极长（> 60 字） | 弹层内 Chip 自动换行，弹层可滚动；作者页副标题最多 2 行省略 |
| 片段搜索无结果 | 按 §4.5 给出「完整署名 / 关键词搜索 / 拆分重试」出口 |
| 网络失败 | 保留现有错误态与重试；不要因为降级策略吞掉错误 |
| 服务端限流 | 沿用现有冷却处理；策略 B 的自动顺延最多 3 页，避免放大请求 |
| 解析结果重复 | 去重；`张三 / 张三（作者）` 只保留一个 |
| 大小写/全半角差异 | 匹配前归一化，展示仍用原文 |

关键文案：

- 弹层标题：`选择要浏览的作者`
- 弹层说明：`该署名包含多位作者或署名说明，选择其中一部分即可搜索署名中包含它的作品。`
- 完整选项：`按完整署名查看「<原署名>」`
- 作者页提示：`正在浏览署名中包含「<片段>」的作品`
- 收藏按钮无结果时：`没有找到署名包含「<片段>」的作品`

## 11. 风险与待验证项

1. **服务端 `a` 参数语义未知（最高风险）**
   若 `a` 只做精确匹配，则必须走「关键词 + 客户端作者过滤」。已有代码注释支持关键词覆盖作者，
   但「部分姓名能否被分词命中」仍需实测；若中文分词导致部分姓名召回为 0，
   则本需求的最终效果依赖 `a` 是否支持子串。**实现第一步必须先跑 §6.1 探针并记录结论。**
2. **关键词路径的召回密度**
   若大量命中来自标题，客户端过滤后单页可能很稀。已用「空页顺延 ≤3 页」兜底；
   若实测密度极低，需回退到策略 A 或提示用户改用完整姓名。
3. **过度拆分**
   `K/DA`、`A/B` 这类笔名会被拆开。用「完整署名」兜底 + 手动编辑覆盖；不追求自动完美。
4. **收藏语义变化**
   用户可能已收藏复合原串。新逻辑不改旧数据，但同一个人可能同时存在「张三」与「张三 / 李四」
   两条收藏。本期接受，后续可做收藏整理。
5. **关注流请求量**
   补作者过滤不增加请求；空页顺延仅在作者页发生且限 3 页，风险可控。

## 12. 决策记录（被否决的方案）

| 方案 | 否决原因 |
|---|---|
| 长按作者文字拖选一部分再搜索 | 与整行点击/横滑冲突，小字号选择精度差，无法标注角色 |
| 所有作者都先弹选择层 | 普通单作者多一次点击，收益低、打扰高 |
| 只按 `/` 和逗号拆分 | 漏掉 `（翻译：王五）`、`原作：张三` 等最常见格式 |
| 作者页直接复用搜索页 | 丢失排序/连载筛选/收藏/分页上下文 |
| 用关键词结果不过滤直接展示 | 标题/标签同名文字会污染「作者作品」语义 |
| 把整串署名继续作为查询、只改 UI 展示 | 无法召回仅署名单人的作品，问题原样保留 |
